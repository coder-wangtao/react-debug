开始循环：Event Loop 是一个持续不断的循环，每一轮都从检查宏任务队列开始。

执行一个宏任务：从宏任务队列中取出一个的任务并执行它。常见的宏任务源包括用户输入事件、setTimeout、网络请求回调，以及 Scheduler 使用的 MessageChannel。

执行所有微任务：在一个宏任务执行完毕后，Event Loop 会立即检查微任务队列。它会循环执行并清空整个微任务队列。如果在执行微任务的过程中，又产生了新的微任务，这些新的微任务也会在同一轮循环中被立即执行。

检查是否需要渲染：清空微任务队列后，浏览器会评估自上次渲染以来是否有任何视觉变化（如 DOM 修改、样式变更），以及当前是否是合适的渲染时机（通常与屏幕刷新率同步，约 16.6ms 一次）。

UI 渲染（可选）：如果需要渲染，浏览器会执行更新 UI 的一系列步骤（Style, Layout, Paint）。这个渲染过程本身不属于宏任务或微任务。 进入下一轮循环：完成渲染（或跳过渲染）后，Event Loop 开始下一轮循环，回到第一步，再次检查宏任务队列。

“微任务的优先级比宏任务高”
是 相对某个宏任务的子任务而言的。
并不是在每轮 Event Loop 最先执行微任务。


✔ 执行完一个宏任务
✔ 清空所有微任务
✔ 决定是否渲染
✔ 再进入下一轮宏任务


console.log("script start");

setTimeout(() => {
  console.log("timeout");
});

Promise.resolve().then(() => {
  console.log("promise");
});

console.log("script end");


整个 script 是一个宏任务
执行 script（宏任务）
script 执行完后 → 执行微任务队列（promise）
下一轮事件循环 → 执行 setTimeout 宏任务
所以微任务不是在 loop 一开始执行，而是在当前宏任务结束后执行。


Event Loop 的基本流程是：
执行当前调用栈中的同步代码。
执行所有可用的微任务。
取出一个宏任务来执行。
重复上述过程。
